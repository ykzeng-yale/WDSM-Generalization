# Frozen first-stage and supplemental production

The first-stage configuration is `first_stage_production.csv`: 39 cells with
1,000 replications each and six paired records per replication. Each of
n=200,800,2000 has same-sample bounded prediction fits in d=2,3,5; independent
training in d=1,2,3,5 with m=n; estimated logistic weights in d=1,2,3,5; and
the qualified Gaussian scalar-score model with M=1,3. All other cells use M=3.
Seeds are 936001 through 936039 in file order. Earlier pilots use separate
seeds and are not pooled with this study.

The supplemental configuration is generated by `wm_supplement_config()` and
written by `supplement_pilot.R`. It fixes eight cells and 200 replications per
cell. The first five replications of every cell are retained from the pilot,
including all failures and clipping. Production continues with IDs6–200.
There are 10,800 records: oracle/feasible × original/stabilized × PATE/PATT in
six cells, and a split PATE plus its two component potential means in two cells.
Component records are paired parts of one dataset, not independent datasets.

`extension_production.R` checks the exact configuration and seeds, freezes R
source and configuration hashes, and creates complete nonoverlapping task
ranges. First-stage tasks1–4 time five replications in each of the four
n=2000,d=maximal branches; those observations remain part of the 1,000.
Tasks5–446 cover the remainder. Supplemental tasks1–8 import the pilot after
checking source hashes, metadata, record grids and byte-identical copies;
tasks9–34 cover the remainder. A task refuses existing outputs. Partial attempts
must be retained and audited before a separately specified missing-ID recovery.

For example, from the package source directory:

```sh
Rscript simulations/supplement_pilot.R /path/to/new/pilot 600
Rscript simulations/extension_production.R prepare supplement \
  /path/to/new/pilot/config.csv /path/to/new/supplement /path/to/new/pilot
Rscript simulations/extension_production.R prepare first_stage \
  simulations/first_stage_production.csv /path/to/new/first_stage
```

Before running a task, set `WDSM_RUN_MANIFEST` to an existing immutable source
snapshot manifest. Pass its task ID explicitly:

```sh
Rscript simulations/extension_production.R run first_stage \
  simulations/first_stage_production.csv /path/to/new/first_stage 1
```

The declared execution budget is one CPU and 3GiB per task, with a 30-minute
scheduler limit and a 1,700-second child-process limit. Batches contain at most
250 replications at n=200,100 at n=800,50 at n=2000. The initial allocation
capped first-stage concurrency at eight tasks and supplemental concurrency
at four. After the supplemental array completed, its four slots were
reallocated to the remaining first-stage array, allowing twelve concurrent
tasks within the same combined limit of twelve CPUs and 36 GiB. This changed
the scheduler throttle, not the frozen task plan, sources, seeds or outputs.
Scheduler speed can vary substantially from timing nodes, so timing results
do not justify removing the reserve. No scheduler submission is performed
by the R runner.

After every task is complete, `extension_collect.R` verifies the frozen
estimator package and every task/replication grid, then calls the corresponding
summary helper. Postprocessing may live in a separate directory, so adding
figures or summaries cannot change the frozen estimator source. It retains
failed-fit denominators, paired comparisons, component sample sizes, Monte
Carlo errors, exact binomial coverage intervals, and source provenance.
Use `first_stage_join.R` or `supplement_join.R` to add independently calculated
geometric benchmarks. Geometry error and estimator Monte Carlo error remain
separate; unresolved geometry does not create a discrepancy z-score.

The completed first-stage study combines disjoint execution ranges and a separately versioned numerical-assertion recovery. All 39,000 declared dataset IDs were reconciled, valid original records were preserved, and all 28 genuine fitted-comparison failures remain reported. Full-record, summary and benchmark audits passed. Aggregate results, recovery counts and numerical qualifications are in [results/RESULTS.md](../results/RESULTS.md); original attempts and execution provenance remain in the private audit archive.
